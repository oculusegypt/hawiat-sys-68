# تقرير مرحلي لتدقيق دورة الطلب والعقد والأصل والمال

**التاريخ:** 2026-10-28  
**الحالة:** تقرير مرحلي؛ سيُحدّث بعد إتمام التحقق المتاح.  
**البيئة:** مراجعة كود وخدمات Node وPHP واختبارات SQLite معزولة. لم تُستخدم قاعدة التشغيل الحالية لكتابة بيانات اختبار.

## مقياس الأدلة

- **مثبت بالكود:** السلوك ظاهر في المسار أو المخطط الذي تمت مراجعته.
- **اجتاز اختبارًا موثقًا:** الاختبار نُفّذ فعليًا في هذه المراجعة ونجح.
- **استنتاج هندسي:** نتيجة تدعمها عدة مسارات، لكنها ليست قياسًا من بيئة الإنتاج.
- **غير متحقق:** لم تُفحص البيانات أو الواجهة أو الخدمة الخارجية اللازمة لإثباته.
- **قرار مالك النظام:** يحتاج سياسة تشغيلية أو قانونية لا يصح تخمينها.

## ما فُحص حتى الآن

- مسارات الطلبات وإسناد السائق/المركبة وإنجاز أوامر العمل، ومسارات العقد والتسليم والاسترجاع والإغلاق.
- مسارات الترحيل المالي والتحصيل والتخصيصات والمرتجعات والأستاذ المالي في Node وPHP.
- مخططات الطلبات والسجلات التشغيلية والتدقيق والحسابات والفترات والتوزيعات المالية.
- حماية المحادثات العامة وربط الجلسة بالزائر، ومسار نبض الزائر.
- اختبارات التكامل على قاعدة مؤقتة أو داخل الذاكرة؛ لم تُستخدم قاعدة التشغيل الحالية للاختبارات.

## نتائج مؤكدة وإصلاحات أُجريت

1. **سقف مرتجعات السداد والفواتير كان يُفحص قبل معاملة الترحيل فقط.** كان يمكن لعدة طلبات ترحيل متزامنة اجتياز فحص منفصل ثم تجاوز أصل السداد أو قيمة الفاتورة مجتمعةً. أُضيف فحص نهائي داخل معاملة SQLite في Node وPHP، واختُبر تزامن المرتجعات في Node، واختُبر فحص PHP ببيانات معزولة. **الحالة: اجتاز اختبارًا موثقًا.**
2. **نبض الزائر العام كان يقبل رقم محادثة من المتصفح ويضعه على جلسة الزائر، بينما صلاحية قراءة المحادثة تعتمد على هذا الربط.** أزيل قبول هذا الربط من Node وPHP؛ تبقى الصلة التي ينشئها الخادم عند بدء المحادثة أو قبول الدعوة. أضيف اختبار يثبت رفض جلسة أخرى مع بقاء وصول صاحب الجلسة. جرى أيضًا منع الرجوع إلى معرّف جلسة ضعيف عند غياب العشوائية المشفرة. **الحالة: اجتاز اختبارًا موثقًا في Node وPHP.**
3. **تصنيف قيد رسوم البنك في مسار ترحيل PHP كان يختلف بين إنشاء المستند وتغيير حالته، ويخالف تصنيف النواة المالية.** وُحّد التصنيف على «مدين» واختُبر في مساري Node وPHP. **الحالة: اجتاز اختبارًا موثقًا.**
4. أُصلح اختبار PHP المعزول الذي كان يفشل بسبب عدم نسخ تبعية لازمة، ووُحّد فحص الإسناد الثابت مع اسم دالة التعارض الموجودة فعليًا. اجتازت الفحوص بعد ذلك.

## ما لم يُفحص أو لم يثبت بعد

- لم تُقرأ الحالة الحالية لقاعدة المعاينة/الإنتاج، ولم تُعدّل سجلات حية أو تُفتح صور أو توقيعات. يوجد سجل تاريخي مؤرخ في 2026-10-26 عن أصل اختبار بقي `rented` وعقد بقي `delivered` بعد تصنيف حركة ملتبسة؛ يجب إعادة فحصه بقراءة مأذونة قبل أي تصحيح.
- لم تُتحقق واجهة الإدارة المسجّلة الدخول تفاعليًا؛ لقطة المتصفح لا تسجل الدخول.
- لم يُثبت تكامل مزود دفع أو استقبال إشعاراته أو المطابقة الآلية مع كشوف البنك. اختبارات الترحيل تختبر قاعدة النظام فقط.
- لم يُنفّذ اختبار استعادة نسخة احتياطية أو تعافٍ بعد فقد اتصال بخدمة خارجية أو تشغيل متوازٍ متعدد العمليات.
- لم يُحسم النظام القانوني/الضريبي أو سياسة تأمين العميل القابل للاسترداد أو شروط فحص الأصل بعد السحب.
- لا يثبت وجود حالة `inspection` وحده وجود بوابة تمنع إعادة الأصل إلى التوافر قبل الفحص.
- لا يوجد في النتائج الحالية إثبات لمسار تعديل تعاقدي ذي إصدارات بعد بدء التنفيذ أو الترحيل المالي.

## الحد المرحلي للاستنتاج

الاختبارات تثبت السلوك المحدد أعلاه في قواعد معزولة فقط. لا تثبت سلامة كل دورة الحياة أو صحة البيانات الحية أو اعتماد المعالجة قانونيًا وضريبيًا. سيُحدّث هذا الملف بعد استكمال مصفوفة المراحل والمخاطر ومعايير القبول والقرارات المطلوبة.
